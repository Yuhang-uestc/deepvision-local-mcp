# Local Vision MCP — 部署与常见问题（用户向）

本手册面向第一次接触本项目的用户：按步骤照做即可部署成功；卡住了先看"常见问题"，绝大多数坑都有现成答案。

## 0. 一句话说明

这是一个给纯文本大模型（DeepSeek 等）补"看图"能力的本地 MCP 服务：图片文件只在本机处理，不直接上传；识别出的文字会进入主模型对话（云端主模型可见）。

## 1. 环境要求

| 依赖 | 说明 |
|---|---|
| Windows 10/11 | 本项目在 Windows 上开发测试 |
| Python 3.9+ | 3.13 实测可用 |
| Ollama | 已安装并启动（托盘常驻） |
| 视觉模型 | `ollama pull qwen3-vl:8b`（约 6GB；想快可再拉 `qwen3-vl:4b`） |
| 可选依赖 | Pillow / ultralytics / PaddleOCR / CLIP（见第 2 步） |

## 2. 部署步骤（照做即可）

### 方式一：一键安装（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1          # 基础安装
powershell -ExecutionPolicy Bypass -File setup.ps1 -Extras  # 含 PaddleOCR + CLIP
```

脚本会依次完成：环境检查 →（可选）装依赖 → 注册 MCP → 安装 skill，可重复执行。

### 方式二：分步安装

```powershell
# ① 进入项目目录
cd <项目目录>

# ② 安装可选依赖（PaddleOCR + CLIP，含首次模型下载，需联网）
powershell -ExecutionPolicy Bypass -File .\install-extra.ps1

# ③ 环境自检（会列出每一项是否就绪）
powershell -ExecutionPolicy Bypass -File .\check.ps1

# ④ 注册 MCP（只追加 local_vision，不会动你已有的 DeepSeek 配置）
#    重要：运行前先完全退出 Codex 桌面应用，注册完再启动——否则运行中的应用可能用旧配置覆盖修改
powershell -ExecutionPolicy Bypass -File .\register-mcp.ps1

# ⑤ 安装识图 skill
powershell -ExecutionPolicy Bypass -File .\install-skill.ps1

# ⑥ 重启 Codex（工具列表是启动时加载的，不重启不生效）
```

> 如果第②步只想用基础功能（描述/检测/分割），可以先跳过 PaddleOCR 和 CLIP，只装
> `python -m pip install ultralytics`，OCR 会自动回退 Windows 内置 OCR。

## 3. 部署完成后的验证

重启 Codex 后，随便说一句：

> 分析这张图 C:/某个/路径.png

看到工具被调用并返回描述即成功。想验证全套能力，依次试：

1. "提取这张图的文字"（OCR）
2. "数一下图里有几个人，框出来"（检测/分割）
3. "找出图里的消防栓"（零样本检测，需权重下载）

## 4. 常见问题（按症状查）

### 4.1 运行 .ps1 脚本报"字符串缺少终止符"或中文乱码

- **原因**：PowerShell 5.1 读取无 BOM 的 .ps1 时按 GBK 解码，UTF-8 中文被误读。
- **解决**：项目内脚本已统一为 UTF-8 with BOM，直接用即可。如果你自己修改过脚本后出现此问题，用支持 BOM 的编辑器（VS Code 选"UTF-8 with BOM"）重新保存。

### 4.2 PowerShell 里 curl 命令报"参数具有二义性"

- **原因**：`curl` 是 `Invoke-WebRequest` 的别名。
- **解决**：用 `curl.exe` 全名。

### 4.3 运行含中文的 Python 脚本出现乱码/问号

- **解决**：执行前设置：
  ```powershell
  $OutputEncoding = New-Object System.Text.UTF8Encoding($false)
  $env:PYTHONUTF8 = '1'
  ```
  或给系统永久设置环境变量 `PYTHONUTF8=1`。

### 4.4 GitHub 下载失败 / 权重下载慢 / 下载被截断

- **原因**：大陆网络访问 GitHub 不稳；部分代理对大文件不可靠。
- **解决**（服务端已内置自动处理）：
  - GitHub release **直连优先**（实测可达，速度可达 17MB/s）
  - 下载走 **curl 断点续传 + 完整性校验**，坏文件自动重下
  - 多镜像 fallback：github → ghfast.top → ghproxy.net
- **手动下载**（如果自动下载一直失败）：
  ```powershell
  curl.exe -L -C - -o <文件名> "https://github.com/ultralytics/assets/releases/download/v8.4.0/<文件名>"
  ```
  需要的权重文件：
  | 文件 | 大小 | 用途 |
  |---|---|---|
  | yolov8n.pt | 6MB | detect_objects 默认 |
  | yolov8n-seg.pt | 7MB | segment_objects 默认 |
  | yolov8s-world.pt | 26MB | detect_by_text 轻量零样本 |
  | yoloe-v8s-seg.pt | 31MB | detect_by_text 增强零样本 |
  | mobileclip_blt.ts | 530MB | YOLOE 文本编码（仅 YOLOE 需要） |

### 4.5 PaddleOCR 报错 Unimplemented / onednn（重点）

- **症状**：`(Unimplemented) ConvertPirAttribute2RuntimeAttribute not support [pir::ArrayAttribute...]`
- **原因**：PaddlePaddle 3.x 的 HPI 新推理引擎在 CPU 上自动启用 oneDNN，该路径有 bug。
- **默认解决**：项目已自动禁用 HPI/oneDNN（`engine="paddle_static" + enable_hpi=False + enable_mkldnn=False`），无需操作。

#### 如果用户不想禁用 oneDNN（备选方案）

禁用 oneDNN 的唯一代价是 CPU 推理稍慢（单张图多一两秒）。如果确实想保留 oneDNN，按优先级：

1. **升级/更换 PaddlePaddle 版本**（治本）：bug 存在于特定 3.x 版本，升级到修复版或换稳定版可能解决。
   ```powershell
   python -m pip install -U paddlepaddle
   ```
2. **退回 PaddleOCR 2.x + PaddlePaddle 2.6.x**（oneDNN 正常）：旧版 API 稳定、无 HPI bug，但识别模型是 PP-OCRv4 且需要相应调整。本项目代码兼容 2.x/3.x 两种 API。
   ```powershell
   python -m pip install "paddlepaddle==2.6.*" "paddleocr==2.*"
   ```
3. **使用 GPU 版 Paddle**：oneDNN 只影响 CPU，GPU 走 cuDNN 不存在此 bug。有 NVIDIA 显卡可装 `paddlepaddle-gpu`。
4. **开启项目开关保留 oneDNN**（在环境变量中设置，然后重启 Codex）：
   ```powershell
   setx PADDLEOCR_KEEP_ONEDNN 1
   ```
   > 仅当你确认 paddle 版本无此 bug（或用了 GPU 版）时才建议开启，否则 OCR 会直接报错。

### 4.6 PaddleOCR 首次调用很慢或要下载东西

- 首次调用会从 modelscope 下载识别模型（100MB+），属正常现象；之后有缓存（`~/.paddlex`）。
- 若提示 `Permission denied: ~/.paddlex`，说明运行用户对该目录无写权限，授予后重试。
- 缓存目录默认 `~/.paddlex`，可用环境变量重定位到有写权限的位置（改完重启 Codex 生效）：
  ```powershell
  setx PADDLE_PDX_CACHE_HOME "D:\paddlex_cache"
  ```
- 多账号/沙箱/服务场景：缓存按 Windows 用户隔离，换账号运行会重新下载模型；请确保运行账号对缓存目录有读写权限。

### 4.7 识图很慢 / 大图超时

- **根因**：8B 模型在 8GB 显存上会部分跑 CPU（`ollama ps` 可见 CPU/GPU 混合）。
- **解决**：
  - 顺手带图让模型走 `mode=quick`（默认 4B、限上下文、精简输出）
  - 拉取 4B 模型提速：`ollama pull qwen3-vl:4b`
  - 大图（宽超 1500px）优先 quick + 局部裁切放大，别直接 detailed
- **可选兜底**：设置 `LOCAL_VISION_MAX_DIMENSION=2048`（重启 Codex 生效）后，发给 Ollama 的大图会自动等比缩到长边 2048px，
  防止 detailed 卡死。注意整图缩放损失全局细节，需要精度的区域仍先用 `crop_image` 裁切放大（那条路径不受影响）。
- **注意**：`max_tokens` 参数在 qwen3-vl 下会导致空输出，勿用；限长靠精简 prompt。

### 4.8 改了代码/新增了工具但不生效

- MCP 工具列表在 Codex 启动时加载。改完 server.py 或安装新 skill 后，**必须重启 Codex**。

### 4.9 数人/定位不准

- 视觉模型不适合报坐标；定位交给 `detect_objects` / `segment_objects` / `cv_locate`。
- 密集人群遮挡严重时，优先 `segment_objects`（数掩膜）并多模型交叉验证。

### 4.10 输出文件写到了奇怪的地方 / 想限制生成目录

- 设置环境变量 `VISION_OUTPUT_DIR` 可强制所有生成文件写入指定目录。
- 默认禁止输出覆盖输入图片。

### 4.11 MCP 工具没出现 / 识图工具列表为空

- **先完全退出并重启 Codex 桌面应用**（新开一个任务/会话不算——MCP 服务器是应用启动时加载的，新任务不会重新读配置）。
- **改配置前必须完全退出 Codex**：`register-mcp.ps1` 会检测运行中的 Codex 并中止（检测不到时也有备份 + 校验 + 回滚兜底），
  但最稳妥的做法是"退出应用 → 运行注册脚本 → 再启动应用"，避免应用用内存里的旧配置覆盖你的修改。
- 重启后仍没有，运行自检（重点看第 5 步"真实握手探针"）：
  ```powershell
  powershell -ExecutionPolicy Bypass -File check.ps1
  ```
- 如果探针提示 `command 是裸 'python'`：重跑一次注册脚本（会自动升级为当前环境的 Python 绝对路径——每个用户在自己机器上运行时解析出各自的路径），然后重启 Codex：
  ```powershell
  powershell -ExecutionPolicy Bypass -File register-mcp.ps1
  ```
- 如果探针提示"工具数量异常"或"握手失败"：确认 `config.toml` 里 `args` 指向的 `server.py` 路径存在、配置可解析；也可以手动启动验证：
  ```powershell
  python C:/绝对路径/server.py
  ```
  然后输入一行 `{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18"}}`，能看到 JSON 响应即服务正常。
- 注意：桌面应用环境里的 `python` 可能不是你终端里的那个 Python（尤其用了 conda/venv 时）。`register-mcp.ps1` 已自动写入当前环境的 Python 绝对路径；如果还有问题，可手动把 `command` 改成你的解释器绝对路径（如 `E:/miniconda3/python.exe`）。

## 5. 隐私与许可

- **隐私**：图片文件只在本机处理（本地 Ollama / PaddleOCR / YOLO / OpenCV），不直接上传原图；但识别出的文字会进入主模型对话，若主模型为云端 API（如 DeepSeek），文字内容会发送到其服务器。需要完全隔离时可搭配本地主模型。
- **许可**：项目代码 MIT；模型权重（yolov8n.pt 等）为 Ultralytics AGPL-3.0 许可，不入库、按需下载，使用前请自行确认合规。
- **密钥**：`~/.codex/config.toml` 含 API Key，绝不提交；项目 .gitignore 已屏蔽。
